How a Lesson Works

A lesson only changes an agent if it sits in a place the agent passes through. In divan there are six such places, from session start to the monthly audit. Two of them are requests: the model reads the rule and usually follows it. Three are code that runs every time, and two of those block a mistake whatever the model wants. The sixth is a monthly report. So where you put a lesson decides when it fires and how strong it is.

Where to put a new lesson

If code can detect the mistake, make the lesson code: a lint check (station 5) or a guard pattern (station 3). It then works whatever the model does.

If the mistake needs judgement (tone, which workflow, what to ask first), it has to be a prose rule. The record skill says where:

  • agent behaviour everywhere → AGENTS.md, "Hard rules"
  • answer shape and stops → skills/working-terms/SKILL.md
  • one workflow → that workflow's SKILL.md
  • a fact or decision → the file that owns it

Every rule change needs your yes first (AGENTS.md, "Records are appended. Rules, statuses and decisions are asked").

What the harness study found about these places

  • Requests depend on the model. On the current model, three of four replayed failures did not happen even without their fix, so some prose rules may be dead weight. The written rule on time estimates did not change Sonnet 4.5's overestimates.
  • Blocks hold, but narrowly. The lint check stopped stale skill counts and the em-dash every time it was active. Yet each new check caught one form of drift, and a different form appeared within one to nine days.
  • The audit is a safety net with holes. One run found about half of the known drift. Three runs merged found about two thirds.

The missing steps, added 23.10.2026

Before the study, lessons were added and never retired. Total rule text grew 3.5-fold in 18 days. These steps are now in divan (Lessons Outlive Their Failures):

  • A lesson register: each rule records where it came from, which model needed it, and a re-test date.
  • An admission rule: a new lesson needs a prediction and a test case.
  • A retirement check: replay the old mistake without the lesson, under a shifted clock, to see whether it is still needed.

Words you will meet

Harness
Everything around the model that guides it: rule files, skills, hooks and checks.
Lesson
A fix written so that a mistake does not repeat: a prose rule or a code check.
Hook
A small script the agent runtime runs at a fixed moment, such as before a shell command.
Lint check
One of the checks lint.py runs on every commit.
Skill
A workflow file the agent loads only when the task needs it.
Drift
Documentation that has gone out of date while the files it describes changed.
Replay
Re-running an old mistake in a copy of the repository, with and without its fix.
